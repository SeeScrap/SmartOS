# Project S3

*[English version](README.md) — ฉบับเต็มพร้อมบันทึกการวัดทุก stage อยู่ที่นั่น*

ระบบปฏิบัติการที่เขียนขึ้นเองสำหรับ ESP32-S3 สร้างจากชั้นเคอร์เนลขึ้นมา

เคอร์เนลตัวนี้ไม่ได้วางทับบน FreeRTOS แต่**เป็นเจ้าของ core 1 ทั้งคอร์** — ESP-IDF
ถูกตั้งค่าเป็น unicore ทำให้ FreeRTOS ไม่เคยสตาร์ตคอร์ที่สอง เคอร์เนลจึงเข้าไปยึด
พร้อมตารางเวกเตอร์ของตัวเอง ตัวจับเวลาของตัวเอง ตัวจัดคิวของตัวเอง และตัวจัดการ
หน่วยความจำของตัวเอง ส่วน core 0 อยู่ต่อเพื่อดูแล USB แฟลช และ PSRAM
และรับงานที่ส่งข้ามมาทาง mailbox

```
 CORE 0                          CORE 1
 IDF + FreeRTOS                  S3-OS
  - คอนโซล USB                    - ตารางเวกเตอร์   (kvectors.S)
  - แฟลช / PSRAM                  - tick CCOMPARE0  (ktime.cpp)
  - คนงานฝั่ง mailbox              - ตัวจัดคิว        (ksched.cpp)
                                  - การสลับงาน      (kswitch.S)
                                  - ตัวจัดการหน่วยความจำ (kheap.cpp)
        ^                                |
        +------- ช่องงานของ kmbox --------+
```

สร้างเพื่อบอร์ดตัวเดียว แต่เขียนให้เอาไปทำต่อได้:
[CONTRIBUTING.th.md](CONTRIBUTING.th.md) บอกวิธี build กฎที่ต้องระวังบน core 1
และวิธีเพิ่มแอปหรือการทดสอบ — [สัญญาอนุญาต MIT](LICENSE)

## ฮาร์ดแวร์

| ส่วน | รายละเอียด |
|---|---|
| ชิป | ESP32-S3-DevKitC-1 **N16R8** — แฟลช QIO 16 MB, PSRAM octal 8 MB |
| จอ | **SPI TFT 2.4" 240x320 ชิป ST7789V** — ใช้แนวนอน 320x240 |
| ทัช | XPT2046 บนบัส SPI เดียวกัน (ยังไม่ได้ใช้) |
| ข้อสังเกต | ขา SDO ของโมดูลไม่ได้ต่อถึงชิปควบคุม จึงอ่านรุ่นจอไม่ได้ ต้องระบุด้วย `-D LCD_FORCE_CTRL` |
| ปุ่ม | 6 ปุ่มลง GND อ่านด้วย pull-up ภายใน |

การต่อสายอยู่ใน [src/board/pins.h](src/board/pins.h) **ห้ามใช้ GPIO 26-37**
บนโมดูลนี้ — เป็นขาของแฟลชและ PSRAM แบบ octal

**ปุ่มใช้สายสองเส้นต่อปุ่ม**: ขาหนึ่งไป GPIO อีกขาไป GND เท่านั้น ไม่ต้องใช้ตัวต้านทาน
UP 4, DOWN 5, LEFT 6, RIGHT 7, OK 15, BACK 16 — ถ้าเป็นปุ่ม tactile 4 ขาให้ใช้
ขาทแยงมุม และถ้ายังไม่ได้ต่อปุ่ม ก็ใช้ `key up` / `hold back` ในเชลล์แทนได้

## build

```
pio run -t upload -t monitor
```

คำสั่งเดียวจบตั้งแต่ clone มาใหม่ แล้ว **อ่านสิ่งที่บอร์ดพิมพ์ออกมา** เพราะมัน
ตรวจสอบตัวเองทุกครั้งที่บูต: 48 รายการในบิลด์ปกติ และ 132 รายการเมื่อใส่
`-D SMARTOS_TEST_APPS` หรือสั่ง `python tools/boot_check.py` ให้รีเซ็ตบอร์ด นับให้ และ
เทียบรายชื่อเคสกับเส้นฐานที่คอมมิตไว้ เพื่อให้รู้ตัวเมื่อมีเทสหยุดทำงานไปเงียบๆ
ส่วนบิลด์ทดสอบแบบอื่นอยู่ท้ายไฟล์ [platformio.ini](platformio.ini)

> **ข้อแก้ไข** บันทึกรายสเตจในฉบับภาษาอังกฤษเขียนเลขไว้สูงกว่านี้ (51 และ 134
> ต่อมา 51 และ 135) เพราะนับทุกบรรทัดใน log ที่ลงท้ายด้วย `OK` ซึ่งมีสามบรรทัด
> ที่ไม่ใช่เทส ได้แก่ log ของ ESP-IDF เอง กับ task สาธิต `[consumer]` และ
> `[mbox]` ที่รายงานผลของตัวเอง ไม่มีอะไรถดถอย — เลขผิด ไม่ใช่เฟิร์มแวร์ผิด

## สิ่งที่สร้างขึ้นมา ทีละชั้น

**เคอร์เนล** — ตารางเวกเตอร์และตัวบันทึก fault ของตัวเอง, การสลับงานเขียนด้วย
Xtensa assembly, ตัวจัดคิวแบบ preemptive ที่สลับงานได้จากใน interrupt,
mutex/semaphore/queue, ตัวจัดการหน่วยความจำสองพูล (128 KB ภายใน + 4 MB PSRAM)
พร้อมแนวกันชนใต้ stack ทุกเส้น

**สองคอร์** — เริ่มจาก AMP (คอร์ละระบบ) แล้วขยายเป็น SMP ที่ตัวจัดคิวเดียว
คุมทั้งสองคอร์

**ชั้นบริการ** — event bus, app model (8 ช่อง เปิด/ปิด/บังคับปิด/ย่อ),
ระบบไฟล์ LittleFS ที่ทนไฟดับ, settings, system log ที่หมุนไฟล์เองและจำกัดอัตราเขียน,
เชลล์ผ่าน USB

**กราฟิก** — framebuffer ใน PSRAM, damage tracking (ส่งเฉพาะส่วนที่เปลี่ยน),
หนึ่ง SPI transaction ต่อสี่เหลี่ยม, ฟอนต์ 5x8 — วัดได้ 15.4 มิลลิวินาทีต่อเฟรมเต็มจอ
(ประมาณ 65 เฟรมต่อวินาที, 9.7 MB/s)

**ส่วนผู้ใช้** — หน้า launcher, task manager ที่มีหน้า performance,
ตัวอ่าน log, แป้นพิมพ์บนจอที่ใช้ปุ่ม 6 ปุ่ม, boot screen, ภาพพื้นหลัง

**วิทยุ** — 2.4 GHz เท่านั้น (Wi-Fi b/g/n + BLE 5) สแกนคลื่นได้ พร้อมเครื่องมือ
สำรวจบนคอมสำหรับเปรียบเทียบเสาอากาศ

## หลักการเดียวที่ยึดตลอดโปรเจกต์

**ไม่อ้างอะไรที่ไม่ได้วัดบนบอร์ดจริง**

ทุกตัวเลขในเอกสารมาจากการทดสอบที่รันบนฮาร์ดแวร์ และบันทึกไว้ทั้งสิ่งที่สำเร็จ
**และสิ่งที่เข้าใจผิดไปก่อน** — เช่น race condition ข้ามคอร์ที่ทำให้บอร์ดวนรีบูต,
ตัวจัดคิวที่ทำให้งานตัวที่สามไม่ได้ CPU เลย, หรือหน่วยความจำที่ชนกับ Wi-Fi
จนบูตไม่ขึ้น ทั้งหมดเจอเพราะวัด ไม่ใช่เพราะเดา

รายละเอียดทั้งหมดอยู่ใน [README ฉบับภาษาอังกฤษ](README.md) ซึ่งไล่เรียงทีละ stage
ว่าสร้างอะไร วัดได้เท่าไหร่ และพังตรงไหนมาก่อน
